# Настройка Supabase — пошаговая инструкция

## Что нужно сделать

Накатить две SQL-миграции через Supabase Dashboard, чтобы создать базу данных и хранилище фото.

---

## Шаг 1. Открой SQL Editor

1. Зайди на [supabase.com](https://supabase.com) и открой свой проект.
2. В левой панели найди раздел **SQL Editor** (иконка выглядит как `< >`).
3. Нажми **+ New query** — откроется пустое поле для SQL.

---

## Шаг 2. Накати миграцию 001 — схема таблиц

1. Открой файл `supabase/migrations/001_initial_schema.sql` в редакторе (VS Code, Cursor и т.п.).
2. Выдели весь текст файла (Cmd+A) и скопируй (Cmd+C).
3. Вставь в поле SQL Editor в Supabase (Cmd+V).
4. Нажми зелёную кнопку **Run** (или Cmd+Enter).
5. Внизу должно появиться: `Success. No rows returned`.

**Что создаётся:**
- Таблицы: `profiles`, `procedures`, `surveys`, `photos`, `push_subscriptions`
- Row Level Security на всех таблицах (пользователь видит только свои данные)
- Триггер: при регистрации нового пользователя автоматически создаётся пустой профиль

---

## Шаг 3. Накати миграцию 002 — хранилище фото

1. Нажми **+ New query** (новый запрос).
2. Открой файл `supabase/migrations/002_storage.sql`.
3. Скопируй содержимое и вставь в поле.
4. Нажми **Run**.
5. Должно появиться: `Success. No rows returned`.

**Что создаётся:**
- Приватный Storage bucket `photos` для фото прогресса
- RLS политики: каждый пользователь может работать только со своей папкой `{user_id}/...`

---

## Шаг 4. Проверь что таблицы созданы

1. В левой панели открой **Table Editor**.
2. Убедись, что в списке есть все 5 таблиц:
   - `profiles`
   - `procedures`
   - `surveys`
   - `photos`
   - `push_subscriptions`

Если таблицы есть — всё хорошо.

---

## Шаг 5. Проверь что RLS включён

1. В **Table Editor** кликни на любую таблицу, например `profiles`.
2. Нажми на вкладку **Policies** (или найди в настройках таблицы).
3. Рядом с названием таблицы должен быть значок **замка** 🔒 — это означает, что RLS включён.
4. Под каждой таблицей должно быть 4 политики: SELECT, INSERT, UPDATE, DELETE.

Альтернативный способ проверить RLS — через SQL Editor:
```sql
select tablename, rowsecurity
from pg_tables
where schemaname = 'public';
```
В столбце `rowsecurity` должно быть `true` для всех 5 таблиц.

---

## Шаг 6. Проверь Storage bucket

1. В левой панели открой **Storage**.
2. Должен появиться bucket **photos** (с иконкой замка — он приватный).
3. Внутри пока пусто — файлы появятся, когда пользователи начнут загружать фото.

---

## Шаг 7. Проверь триггер

Чтобы убедиться, что триггер создан, выполни в SQL Editor:
```sql
select trigger_name, event_manipulation, event_object_table
from information_schema.triggers
where trigger_name = 'on_auth_user_created';
```
Должна вернуться одна строка с `on_auth_user_created`.

---

## Что делать если что-то пошло не так

**Ошибка "relation already exists"** — таблицы уже созданы (возможно, запустила дважды). Не страшно.

**Ошибка с правами** — убедись, что ты в своём проекте, а не в чужом.

**Миграция прошла, но таблиц нет** — обнови страницу (F5) и проверь снова.
